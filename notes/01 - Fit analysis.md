# Fit analysis (idea v0.1 vs. challenge and criteria)

## What the challenge asks for
"Create an interactive game in which the player **designs, manages and simulates** a complete space mission, making **engineering decisions with limited resources** and seeing the effect of each choice." Level: Intermediate · Beginner/Youth.

## Fit with the challenge text
| Challenge verb | Does the idea cover it? | Comment |
|---|---|---|
| Design | **Partly** | Choosing items and objectives is packing cargo, not designing the mission. Main gap. |
| Manage | Yes | Resources, team, improvisation, decision to return. |
| Simulate | Yes, simplified | Consumption per sector, events, evaluation. |
| Complete mission | **Partly** | It is a field trip from a habitat. Defensible, but a literal judge may object. |
| Engineering decisions | Yes | Adjacency, mass, power, trade-offs. |
| See the effect of each choice | Yes | If the UI shows costs before confirming (the doc already plans this). |

## Judging criteria
| Criterion | Status | Risk |
|---|---|---|
| Impact | Medium. Improved by an educational final screen ("what NASA would do"). | Low |
| Creativity | **Strong**: adjacency in the inventory + improvisation with visible cost. | Low |
| Validity | Depends on having a playable prototype. Today there is only a document. | **High** |
| Relevance | Weak if the elevation data only becomes a hidden number. | **High** |
| Presentation | The game is hard to explain in 30 s or 7 slides. | **High** |

## Submission rules the idea must respect
- At least 1 NASA resource **listed in the challenge's Resources tab**; without it, the project cannot compete globally. **I could not check that tab** (must be checked on the site). Mars Trek, MOLA and PDS are plausible candidates, but not confirmed.
- Project page in English; demo = video up to 30 s **or** up to 7 slides, at a public link.
- Under-18s: no face, voice or name in the demo.
- AI: declare where and how it was used; AI-generated images or videos carry a watermark.
- List references for third-party data, code, images, sounds and fonts (art and audio packs go here).

## Strengths of the document
Good design logic (pillars, risks, minimum scope, implementation order). The doc itself already recommends a vertical slice and data that changes the rules.

## Weaknesses of the document
1. The minimum scope still has ~13 content items for ~25 h with no prototype.
2. First-person grid (blobber) is the most expensive part in art and code and scores the least.
3. NASA data only appears as "cost per sector", without the player seeing the connection.
4. There is no mission **design** phase.
5. Nothing about how a judge plays in 2 minutes (tutorial, web build, plan B).
6. Open decisions (section 18 of the doc) must be closed today.
